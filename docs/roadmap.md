# 个人作图工具箱施工方案

## 先定目标和技术路线

可行。假定主要用途是**单人在本机处理表格和实验数据，以界面选数据、画图、出图，并经常复用原来的设置**。先验证这一条工作流。图表数量增加不会使 Python 失去优势；真正决定技术路线的是使用形式、数据体量、交互要求和导出要求。

| 路线 | 适合的情况 | 成本与取舍 |
| --- | --- | --- |
| **首选：改造 SciPlot（TypeScript / React / ECharts）** | 常用鼠标编辑、希望浏览器界面在本机运行，当前数据多为常规表格。 | 已有画布、数据表、轴和导出，可较早验证成果；大表需 Worker、虚拟表格和降采样；精细统计另接计算模块。 |
| **Python 优先：pandas + Matplotlib/SciPy + CLI 或 Notebook** | 核心工作是批量出图、拟合、可重复脚本；手工拖拽为辅助。 | 容易实现计算、矢量输出和自动化。加简易表单可用 Dash + Plotly；若需要复杂画布、撤销、多面板和精细状态同步，加 UI 的成本会上升。Plotly 的[静态导出](https://plotly.com/python/static-image-export/)依赖 Kaleido，Kaleido v1 需可用的 Chrome/Chromium，WebGL 图层在矢量格式中部分栅格化。 |
| **Python 桌面：PySide6 + Matplotlib / PyQtGraph** | 要桌面窗口、深度使用本地文件、设备或实时数据。 | Python 能写前端和计算编排。[PyQtGraph](https://github.com/pyqtgraph/pyqtgraph)可做高频预览，Matplotlib 可做出版图；要验证两条渲染链的样式一致性，并维护安装包和平台测试。 |
| **混合：TypeScript UI + Python 计算** | 在可视化编辑之外，已有反复发生的拟合、批量或大文件需求。 | 按需用 [Polars](https://docs.pola.rs/user-guide/lazy/using/)处理表或 [DuckDB](https://duckdb.org/docs/stable/clients/python/overview)做本地 SQL，SciPy 做数值分析。多一个运行时、进程和接口要维护，等真实需求出现再上。 |

如果现有 Veusz/LabPlot 搭配少量脚本已跑通你的典型任务，也可以直接用成熟应用，将开发量集中在你的导入规则、模板和批量命令。首选路线的判断关键是：**SciPlot 的选数据、工程保存和导出能否改到满足你的真实样例。** 性能问题优先测读入、转换、传输和绘制哪段慢；绘制十万点时，换语言不会自动减少需要渲染的点。

## 功能清单

P0 是首个可用版本，P1 是使用后优先补充，P2 只在需求明确时做。可行性按这条路线估计；「随用随加」的成本通常来自边界情况和验证，并不等于写一个按钮的时间。

| 模块与功能 | 优先级 | 必要性与可行性 |
| --- | --- | --- |
| CSV/TSV/Excel/剪贴板；导入预览、分隔符/编码、表头、Excel 工作表和区域 | P0 | 入口。SciPlot 有解析基础；预览先做常见配置，持续记录坏行、重复列名和行号。中。 |
| 列类型覆盖、日期解析、保留编号前导零、单位与空值 | P0 | 决定图是否画对；源值与解析值分开。日期先支持显式格式，无时区日期与带时区时间区分。中。 |
| 数据表预览、列选择、按行号区间或条件筛选、稳定排序 | P0 | 核心。表格和图共享同一份视图；区分源行号与筛选后行位置，显示纳入/排除数量。中。 |
| X/Y/颜色分组、同图多曲线、点线柱 | P0 | 用户最常用的图。预设只填默认值，每条序列可独立选数据。高。 |
| 线性/对数/日期/分类轴，标题、单位、范围、刻度格式、刻度方向 | P0 | 用户核心。校验上下限，对数轴明确报告非正数；日期/分类轴不按数值轴解释。中。 |
| 缺失值选择、散点忽略/折线断开、非法数值提醒 | P0 | 没有规则会造成误读。默认保持折线空缺，分别统计条件排除和无效数据。高。 |
| 图例、颜色、点型线型、字号、画布尺寸、色盲友好配色 | P0 | 支撑日常输出；复用 SciPlot 的主题并保留每序列覆盖。高。 |
| 导出 SVG/PNG，保存/重开工程，另存参与绘图的 CSV | P0 | 图能交付、结果能重做。验证物理尺寸、像素、裁切、字体；保留源行与筛选记录。中。 |
| 软件内撤销/重做与只读原始数据 | P0 | 防止误改源；沿用可用 UI，把修改存为有审计的操作，不将拖点默认用作修改数据。中。 |
| 工程模板、批量换源、版式/期刊预设、工程快照 | P1（若经常重复则提前） | 复用价值大。引用模板时校验列名、类型与单位；同时支持可携带数据快照和只含配置的配方。中。 |
| 多级条件、计算列、单位转换、归一化、基线校正 | P1 | 实验数据高频；先用白名单操作，参数与顺序可重放，显示计算异常。中。 |
| 合并、拼接、宽长表转换、分组聚合、重采样 | P1 | 多组实验和日志有用。预防多对多 join 扩行，明确时间桶与聚合规则。中。 |
| 直方图、箱线/小提琴、相关矩阵、热力图 | P1 | 用于分布和质量检查，部分可复用。明确分箱、四分位或相关系数的定义。高。 |
| 错误棒/置信带、双 Y 轴、共享轴、组图 A/B/C、参考线和标注 | P1 | 科研常用，已有部分能力。区分 SD、SEM 和 CI；明确轴归属、数据坐标或画布坐标。中。 |
| 描述统计、拟合残差、参数/置信区间、平滑/积分/峰检测 | P1–P2 | 常做拟合时价值高。先提供统计量与线性拟合；按真实数据加非线性、信号分析，输出算法和参数。中到低。 |
| 交互缩放、框选、数据点回查、联动筛选 | P1–P2 | 查异常很有效。缩放仅改变显示；框选结果想变成筛选须显式保存；降采样后仍可追溯。中。 |
| PDF、可导入排版软件的矢量图、透明背景和字体选项 | P1（若投稿刚需则提前） | 有现成 PDF 路径，中文字体可用性、嵌入和物理尺寸仍须验收。中。 |
| Parquet、SQLite、SQL 查询、实验仪器格式 | P2（随数据来源提前） | 有明确来源再做。查询只取需要的列行；每个专用格式都需有真实样本与坏文件用例。中。 |
| 百万行数据、实时追加/监测、高频时序 | P2 | 除非测量证明有需求。列式查询、分块、虚拟表格、按视图降采样；实时另需缓冲和刷新频率控制。中到低。 |
| 无界面 CLI、任务批处理、可复现报告、生成代码 | P2（脚本是主流程则提前） | 重复任务收益高。CLI 可借同一渲染器，例如本地无头浏览器，避免网页和批处理结果漂移。中。 |
| 地图、3D、动画、发布仪表盘、共享协作、插件 SDK、AI 选图 | P2 | 领域明确后才值回维护。分开做小原型；协作增加身份、同步和部署的设计成本。低。 |

## 模块怎么拆

```text
DataSource（原始文件、导入配置、校验摘要）
  → Dataset（有稳定 ID 的列、类型、原始行标识）
  → DataView（筛选、计算、排序、分组；输出视图和诊断）
  → PlotSpec（序列字段映射、坐标轴、标注、样式、布局）
  → Renderer（SciPlot/ECharts） → SVG / PNG / PDF
Project / Recipe 将数据引用或快照、DataView、PlotSpec 和版本串起来
```

先把解析、筛选与坐标验证做成可脱离 UI 调用的函数。引用字段用 ID，不用当前列下标；模板换源时用显式映射或按列名和类型匹配，有冲突就提示。图层可以绑定不同视图；图表只消费视图，坐标范围不会改变筛选结果。源文件保持原样，派生数据单独保存或按步骤重算。项目文件加 `schemaVersion` 和校验，有格式变更就提供迁移；共享配方时可以只保存配置，不打包原始数据。

渲染先保留一个实现，图的配置不直接等同于 ECharts 配置。未来若加入 Python，只接明确定义的查询或分析操作：传视图参数与数据引用，返回结果、统计与诊断。扩展点先是内部函数和数据约定，等有第二种真实来源/渲染器才抽完整接口。

界面可沿用「左边数据表/筛选、中间画布、右边图层与 X/Y 配置」。用户选条件后即时显示有效行数；对数轴值非法、高于渲染上限等情况在对应位置提示。导出时如有抽样要明确标记；导出用于复核的数据表默认保留完整筛选结果。

## 分期与验收

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| **0：试用与取舍，0.5–1 天** | 找三份样例：有前导零/空白的 Excel、两组实验曲线、较大的 CSV。试 SciPlot 和 Veusz，记录每份数据走完整流程的阻碍。 | 以编号/Excel 区域、筛选、坐标、中文 SVG/PDF 等为门槛。若 SciPlot 主要缺口可局部改造，复制 MIT 代码到独立开发仓并保留出处；若已有工具够用，优先写复用脚本；若需求主要是脚本，转 Python 路线。 |
| **1：作图闭环，约 1–2 周** | 类型和导入预览、数据视图、字段映射、轴校验、SVG/PNG 与工程保存。画布主要复用。 | 样例里 `00123` 保持文本，选定行数与人工核对一致；改变轴范围不改变参与绘图的行；对数轴的非正值可解释；重开工程得到相同数据与图形配置。用一个固定尺寸样例验证像素与矢量尺寸。 |
| **2：复用和分析，约 1–2 周** | 模板换源、常用计算列/分组、误差棒、组图与 PDF，按实际需求排序。 | 用同模板替换第二份真实数据；给缺列或单位不一致的文件时提示并保留原工程；中文图导出后检查字体、裁切、物理尺寸与后续编辑情况。 |
| **3：按数据扩容** | 做性能基线，按测量加入解析 Worker、虚拟表格、降采样、Python、DuckDB 或 CLI。 | 在同一台机器上用固定样例比较导入时间、变更筛选/轴到重绘的延迟、峰值内存、导出耗时。10 万行 × 10 列可用作首轮测量档，若 1 万行已符合真实工作量，先交付；若项目拖动/筛选明显卡顿，再针对卡点改造。 |

时间按单人进行粗估，依赖真实数据、导出标准和复用程度。第一轮不追求图库数量；先完成一张你确实需要的图，并用第二批数据重新生成它。首批验证覆盖错误输入、类型转换、筛选语义、工程重开和导出结果，图表类型增加后再补对应样例。
